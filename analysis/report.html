1. Study design

The evaluation uses a fixed training window from 2026-02-23 to just before 2026-08-24. The following 56 days form an untouched holdout ending on 2026-10-19. Model choice for the ridge calendar model uses only a validation slice inside the training period.

  • Historical median: median free spaces for the same garage, weekday and local hour in the training window.
  • Previous week: the observed free-space count exactly seven days earlier.
  • Ridge calendar: regularized linear model on cyclical hour, weekday and annual seasonality, weekend, trend and capacity. It receives no holdout targets during fitting.
Scope. This evaluates reported free-space counts, not physical ground truth. It is a forecasting comparison, not a reservation guarantee. Events, tariffs, road conditions and new exceptional opening hours are not included.

5. Reproducibility and SQL

The pipeline writes validated observations and the audit table to SQLite. Two indexes support time-series and weekday/hour queries. The database is generated locally and excluded from Git because the source export can be downloaded again.

python -m pip install -r requirements.txt
python basel_parking/build.py --refresh
python analysis/run_analysis.py
python -m unittest discover -s analysis/tests -v

Useful SQL queries are stored in analysis/sql/quality_summary.sql. Aggregated model metrics, predictions and audit results are exported as CSV in analysis/outputs/.

6. What this project demonstrates

  • Data ingestion from a public API and deterministic cleaning.
  • A documented SQLite schema and reproducible analytical outputs.
  • Chronological train, validation and holdout boundaries that prevent target leakage.
  • Comparison with simple baselines before accepting a model.
  • Per-garage results, uncertainty for the main comparison and explicit limitations.
